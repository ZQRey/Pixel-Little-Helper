## 🚀 Текущий спринт: Автоматизация клиента и управление окнами

### 1. [x] Умный контроль запуска NCALayer (`NcaLayerWatchdog`)
- [x] **Задержка запуска ~7 минут:** При старте помощника выдерживается задержка 7 минут (`TimeSpan.FromMinutes(7)`), давая операционной системе полностью завершить фоновые службы и автозапуск.
- [x] **Проверка активного процесса:** Проверяется наличие процесса `ncalayer` в системе (`Process.GetProcessesByName("ncalayer")`).
- [x] **Исключение дублирования:** Если процесс уже активен — повторный экземпляр НЕ запускается, что полностью устраняет ошибку *«занят порт»*.
- [x] **Автозапуск при отсутствии:** Если процесса нет — находится исполняемый файл по стандартным путям системы и запускается `ncalayer.exe`.
- [x] **Оповещение при отсутствии программы:** Если `ncalayer.exe` не найден в системе — выводится локализованное уведомление пользователю: *«Приложение NCALayer не найдено в системе»* (с поддержкой RU, KK, EN, ZH).

---

### 2. [x] Проверка пользователей и очистка ресурсов (`SessionWatchdog`)
- [x] **Таймер проверки (2.5 минуты после старта):** Инспекция сессий стартует через 2.5 минуты после входа пользователя.
- [x] **Анализ активных сессий Windows:** Сессии определяются через Win32 `WTSEnumerateSessions` + `WTSQuerySessionInformation` и fallback-парсер `quser.exe`.
- [x] **Отключение пользователей в «ожидании»:** Если пользователей больше одного:
  - Определяется текущий активный пользователь на консоли.
  - Находятся сессии других пользователей в ожидании / отключении (например, заблокированная сессия `sadjan`).
  - Выполняется принудительное завершение неактивной сессии через `WTSLogoffSession` и `logoff.exe <Id>` для экономии памяти и ресурсов процессора.
  - Пользователю выводится уведомление: *«Завершена неактивная сессия пользователя {username} для освобождения ресурсов»*.
- [x] **Перезапуск NCALayer после очистки сессий:**
  - Проверяется процесс `ncalayer`: если остался от предыдущего пользователя или завис — принудительно завершается и перезапускается под текущим пользователем.
  - Если процесс не запущен — запускается `ncalayer.exe`.
  - Если приложение не найдено — пользователю показывается уведомление.

### 3. [x] Режим отображения «Поверх всех окон» (`Topmost`) для окон и диалогов
- [x] **Окно создания заявки (`TicketWindow`):**
  - Установлен `Topmost = true` и привязка `Owner = this`.
  - Устранена критическая ошибка с `NativeMethods.Bottom` и хуком `DesktopAnchor`, которые принудительно утягивали окно заявки на дно рабочего стола под все окна. Окно теперь гарантированно открывается на переднем плане поверх всех окон с фокусом в поле ввода.
- [x] **Служебные окна и диалоги помощника:**
  - `SuperAdminWindow`, `EmergencyDialogWindow`, уведомления и меню открываются поверх всех окон (`Topmost = true`, `Owner = this`).
- [x] **Мессенджер — в обычном режиме:**
  - В `MessengerWindow` зафиксирован стандартный режим (`Topmost = false`), чтобы не перекрывать окна во время переписки.

## 🚀 Новый спринт: Филиалы, экстренные коды, синхронизация кабинетов и поведение помощника

### 1. [x] Разделение филиалов по первой букве имени компьютера
- [x] **Конфигурация префиксов в модели `Branch`:** Добавлено поле `ComputerPrefixes` (строка, разделяемая запятыми/пробелами, регистронезависимо).
- [x] **Предустановленные соответствия по умолчанию:**
  - `N` → Поликлиника и детская поликлиника
  - `R` → Роддом
  - `D` → Детская больница
  - `B` → Больница
- [x] **Настройка в веб-панели (`app.js`):** В форме редактирования филиала добавлено поле ввода «Буквы / префиксы ПК» с возможностью произвольного указания (любые буквы, не только N, R, D, B).
- [x] **Миграция БД и валидация:** Обновлены `Branches.EnsureSchemaAsync` и `ValidateAsync` (SQLite/PostgreSQL).

---

### 2. [x] Отработка экстренных вызовов строго по филиалу
- [x] **Определение филиала инициатора:** При вызове тревожного кода в `HelperHub.TriggerEmergencyAlert` филиал вычисляется по первой букве `MachineName` вызывающего ПК (или привязанному `BranchId`).
- [x] **Таргетированная рассылка в рамках филиала:** Сигнал отправляется группе `BranchAgents:{branchId}` (только ПК соответствующей больницы/поликлиники).
- [x] **Сквозной контроль для руководства:** Администраторы и SuperAdmin (группа `PanelStaff`) получают информацию о тревогах всех филиалов без ограничений.

---

### 3. [x] Автоматическая привязка клиентов и пользователей к филиалу
- [x] **Определение филиала при регистрации ПК:** При вызове `RegisterComputer` по первой букве имени ПК находится соответствующий филиал и сохраняется в `Computer.BranchId`.
- [x] **Автопривязка пользователя:** Если текущий пользователь ПК имеет роль `User` или `Operator`, автоматически выставляется `user.BranchId = branch.Id`.
- [x] **Исключение для администраторов:** Пользователи с ролями `SuperAdmin` и `Admin` сохраняют глобальный доступ, их `BranchId` автоматически не перезаписывается.

---

### 4. [x] Адресный вызов «Код Синий» (СЛР / Реанимация)
- [x] **Назначенные специалисты «Кода Синий»:** Настройка в веб-панели (в разделе экстренных оповещений) списка ответственных специалистов/логинов реанимационной бригады `CodeBlueResponsibleUsers`.
- [x] **Вызов из кабинета:** При активации «Код Синий» (например, из кабинета 120) передается номер кабинета вызова.
- [x] **Срабатывание только у назначенных специалистов:** `EmergencyAlertNotice` отправляется исключительно на компьютеры назначенных специалистов данного филиала (группы `AgentUser:{username}`). У остальных пользователей экран тревоги не блокирует работу.
- [x] **Информационный экран:** На мониторах назначенных специалистов открывается полноэкранный алерт с текстом: *«КОД СИНИЙ: Срочная реанимация! Кабинет {номер}»* и звуковым сигналом.

---

### 5. [x] Анимация «Танец» при входящих сообщениях
- [x] **Реакция помощника на входящие сообщения:** В `PetWindow.cs` при получении входящего личного или группового сообщения мессенджера (и срочных уведомлений) активируется анимация танца `React(PetState.Dance, 5)`.
- [x] **Визуальный акцент:** Помощник танцует вместе с отображением облачка с текстом или значка непрочитанного сообщения, привлекая внимание пользователя.

---

### 6. [x] Первичный запрос и двусторонняя синхронизация номера кабинета
- [x] **Проверка кабинета при запуске клиента:** Помощник проверяет поле `TicketRoom` в локальных `Settings`.
- [x] **Диалог ввода кабинета (`RoomPromptWindow`):** Если кабинет не задан (пустая строка), показывается стильное окно поверх всех окон с запросом: *«🏢 Укажите номер кабинета»*.
- [x] **Сохранение и передача на сервер:** После ввода пользователем сохраняется кабинет в локальный `config.json` и отправляется на сервер через SignalR `UpdateClientRoom(room)`.
- [x] **Отображение и редактирование в веб-панели:** В карточках пользователей и таблице ПК отображается поле «Кабинет» с возможностью изменения администратором.
- [x] **Серверный пуш обновлений на клиент:** При изменении кабинета администратором на сервере отправляется событие SignalR `ClientRoomUpdated(newRoom)`, клиент обновляет свой `config.json` на лету без перезапуска.

- [x] **Удаление переключателя режимов:** В `PetWindow.cs` убран из контекстного меню пункт *«Отображение помощника»* (выбор «Обычный режим», «Фон под окнами» и «Скрыть помощника»).
