# HTTP, HTTPS и сертификат AD CS для Control Center

Панель доступна по `http://helper.gp1.loc` (80) и `https://helper.gp1.loc` (443). HTTP сохранён без перенаправления, поэтому уже установленные клиенты продолжают работать. Для новых установок можно передавать `SERVERURL="https://helper.gp1.loc"`.

## Docker Compose

Запуск из корня репозитория:

```sh
docker compose up -d --build
docker compose ps
```

Контейнер proxy (nginx) принимает HTTP и HTTPS и передаёт запросы серверу на внутренний порт 5000. Он поддерживает WebSocket/SignalR и загрузку MSI до 200 MiB. Порт 5000 наружу не публикуется. Сертификат и закрытый ключ находятся в постоянном Docker volume `pixel-little-helper_tls-data`; закрытый ключ не хранится в Git или на контроллере домена. Не удаляйте этот volume командой `docker compose down -v`.

При первом запуске в пустом окружении init-tls создаёт ключ и однодневный самоподписанный сертификат для первоначального запуска. До выполнения задачи AD CS такой сертификат не является доверенным. Перезапуск существующей установки сохраняет выданный AD CS сертификат.

## Автоматическое продление

На `dc01.gp1.loc` зарегистрирована задача **Helper-Certificate-Renewal**, работающая под SYSTEM ежедневно в 03:30 по локальному времени dc01, со случайной задержкой до 10 минут. Проверка обновляет сертификат, когда до окончания остаётся не больше 60 дней. При ошибке предусмотрено три повтора через 15 минут и запуск после пропущенного расписания.

Задача запрашивает сертификат WebServer у `dc01.gp1.loc\gp1-DC01-CA`. Учётная запись компьютера `GP1\DC01$` уже имеет право Enroll для этого шаблона. Пароль AD для задачи не нужен.

Файлы задачи: `C:\ProgramData\HelperCertificateRenewal` (доступ только SYSTEM и администраторам). `renewal.log` содержит результат; `ssh-error.log` — диагностику соединения. SSH-ключ предназначен только для операций status/request/install и не предоставляет интерактивный доступ. SSH host key сервера закреплён в known_hosts.

Сервер проверяет имя helper.gp1.loc, цепочку AD CS, назначение sslserver, соответствие закрытому ключу и увеличение срока действия. После установки выполняются проверка конфигурации и плавная перезагрузка nginx; при ошибке активации восстанавливается предыдущий сертификат.

Проверить задачу на dc01:

```powershell
Start-ScheduledTask -TaskName Helper-Certificate-Renewal
Get-ScheduledTaskInfo -TaskName Helper-Certificate-Renewal
Get-Content C:\ProgramData\HelperCertificateRenewal\renewal.log -Tail 10
```

Ожидаемый LastTaskResult — 0. Вручную повторять выпуск на каждом компьютере не требуется. Доменным ПК нужен доверенный корневой сертификат `gp1-DC01-CA`; на недоменных устройствах его необходимо установить в доверенные корневые центры сертификации.

После смены IP обновите DNS helper.gp1.loc. Имя продолжит работать с прежним сертификатом. Текущий сертификат также содержит IP 172.16.16.61; новый IP потребует обновления SAN в скриптах и перевыпуска.

При переносе сервера восстановите TLS volume, обновите адрес и закреплённый SSH host key на dc01 после проверки нового ключа и установите ограниченный SSH-канал. При переносе контроллера домена перенесите задачу и выдайте новому компьютеру право Enroll на WebServer.

## Повторная настройка задачи

Скопируйте `LitleHelperServer/tls` на dc01 и от администратора запустите `Install-HelperRenewal.ps1 -SshHostKey 'ssh-ed25519 AAAA...'`. Значение получите из `/etc/ssh/ssh_host_ed25519_key.pub` сервера по уже проверенному SSH-соединению, без комментария в конце ключа. Скрипт создаёт отдельный ключ, задаёт безопасные права и регистрирует задачу.

Выведенный открытый ключ добавьте отдельной строкой в `/home/zqrey/.ssh/authorized_keys`:

```text
restrict,command="/home/zqrey/Pixel-Little-Helper/LitleHelperServer/tls/renewal-ssh.sh" ssh-ed25519 AAAA...компонент-ключа...
```

Замените компонент ключа реальным выведенным ключом. Выполните `chmod 700 /home/zqrey/Pixel-Little-Helper/LitleHelperServer/tls/renewal-ssh.sh`, затем запустите задачу. Пользователь zqrey должен иметь доступ к Docker. На текущих серверах эти действия уже выполнены.
