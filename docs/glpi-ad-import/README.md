# Предотвращение ошибок заявителя GLPI

Причина инцидента 08.10.2026: snezhko_o отсутствовал в GLPI, хотя учётная запись была в AD. Учётные записи GLPI ранее появлялись после первого входа пользователя либо ручного импорта. Ошибка помощника «должен существовать ровно один пользователь» в этом случае означала отсутствие заявителя.

Пользователь импортирован штатной командой GLPI `ldap:synchronize_users`. Выполнен первичный импорт ещё 408 отсутствовавших пользователей AD.

На glpi под zqrey установлен `/home/zqrey/glpi-import-ad-users.sh`. Пользовательский crontab запускает его каждую минуту. Файл `import-new-users.sh` — копия установленного скрипта. `flock` исключает одновременные запуски; каталог LDAP №1 (`gp1.loc`) настроен в GLPI. Импортируются только новые активные пользователи AD. Существующие пользователи, их права, история заявок и локальные учётные записи не изменяются этим заданием. Права новых пользователей определяются штатными правилами GLPI для LDAP.

После создания новой учётной записи AD дайте очередному импорту завершиться (обычно около минуты), прежде чем отправлять первую заявку. Предварительный вход сотрудника в GLPI больше не требуется.

Проверка на сервере:

```sh
systemctl is-active cron
crontab -l
/home/zqrey/glpi-import-ad-users.sh
tail -30 /home/zqrey/logs/glpi-ad-import.log
```

Копия предыдущего crontab: `/home/zqrey/crontab-before-helper-ad-import-20261008.txt`. После изменения пароля учётной записи чтения LDAP обновите его в настройках каталога GLPI и проверьте импорт вручную. При переносе GLPI восстановите задание cron вместе с настройками LDAP; оно находится на хосте GLPI, а не в контейнере Control Center.

Дубликаты логинов и отключённые пользователи требуют отдельной проверки: выбирать произвольную учётную запись заявителя нельзя. В данном инциденте дубликатов не было.
