# LitleHelperClient / PixelHelper 1.2.6

С версии 1.2.6 форма заявки содержит филиал и кабинет. [Инструкция](../docs/BRANCHES.md).

С версии 1.2.5 обычные кнопки расположены в две колонки над помощником, имеют закруглённые углы, мягкую тень и подсветку при наведении.

С версии 1.2.4 пункты «Кнопки супер админа» и «Закрыть помощника» находятся в контекстном меню по правому клику на помощнике. Левый клик показывает обычные кнопки.

С версии 1.2.3 помощник показывает сообщения SuperAdmin в облачке над собой. Для привязанного ПК доступен отдельный пункт «Кнопки супер админа»: вход AD/локальной учётной записью, настроенные кнопки сообщений, выбор всех или отдельных получателей. Инструкция: [CLIENT-MESSAGES.md](../docs/CLIENT-MESSAGES.md).

WPF-помощник Windows 10/11 x64 на .NET 8. Сохранены прозрачность, анимации, перетаскивание, автозапуск, сон и клики сквозь пустые области. Добавлены SignalR, инвентарь, административные команды и GLPI.

Свежий MSI: `artifacts/release-1.1.3/PixelHelper.msi`. Для переносного запуска EXE нужны **все** соседние файлы `artifacts/release-1.1.3/publish`. Старый `artifacts/publish` не является новым релизом. Закройте старого помощника перед запуском нового: действует ограничение одного экземпляра на пользователя.

## Настройки

Получите ключ для имени ПК в панели сервера, затем создайте `%APPDATA%\PixelHelper\config.json`:

```json
{
  "x": null, "y": null,
  "serverUrl": "http://helper-server",
  "hubUrl": null,
  "clientToken": "КЛЮЧ-ДЛЯ-ЭТОГО-ПК",
  "enableAdministrativeCommands": true,
  "allowRemoteCommands": false
}
```

MSI 1.1.3 предлагает адрес сервера при ручной установке. Для тихой установки передайте публичное свойство SERVERURL (пример ниже). Адрес хранится в HKLM\Software\PixelHelper\ServerUrl (64-битная ветка) и имеет приоритет над serverUrl в пользовательском config.json. При обновлении без SERVERURL сохраняется установленный адрес; при первой установке по умолчанию используется http://helper-server. Используйте абсолютный HTTP/HTTPS-адрес без логина, пароля, query и fragment. Изменение применяется после перезапуска помощника. MSI не задаёт ключ clientToken.

hubUrl задаёт полный адрес явно и имеет приоритет над адресом из MSI; иначе используется serverUrl + /helperHub. Без ключа соединение не запускается. Если user config отсутствует, читается config.example.json возле EXE. Перезапуск применяет изменения. Координаты сохраняются при перетаскивании/выходе; первое «Да» добавляет HKCU/Run, «Нет» отмечает первое появление и закрывает помощника. Последующий ручной запуск разрешён без автозагрузки.

## Онлайн и офлайн

WithAutomaticReconnect дополнен повторами первого подключения. Регистрация отправляет ПК, AD-логин, домен, IP и Windows. WMI/реестр читаются в фоне при подключении и по запросу администратора. Во время реконнекта и без сети показываются ровно пять кнопок:

1. Поиск файлов и папок — explorer.exe search-ms:.
2. Открыть DMED — https://krg.dmed.kz.
3. Открыть EISZ — https://www.eisz.kz.
4. Отключить автозапуск — удаление HKCU/Run PixelHelper.
5. Закрыть помощника.

Старый actions_cache.json не используется меню. ApiClient сохранён для совместимости прежнего REST-кода/тестов, но WPF 1.1 подключается через HubConnectionService. Серверные кнопки приходят OnButtonsUpdated, при регистрации/реконнекте и каждые 30 минут; максимум 12. Онлайн также доступны закрытие и отключение автозапуска; офлайн они входят в фиксированные пять и не дублируются.

Ticket открывает поле текста без пароля. Хаб CreateTicket(title, description) получает username/PC из регистрации соединения. Успех: «Заявка №ID успешно создана!». При ошибке текст сохраняется; GLPI-секреты находятся только на сервере.

## Команды

enableAdministrativeCommands регулирует RPC; allowRemoteCommands отдельно разрешает EXE-кнопки. Команды выполняются с правами пользователя, при отказе доступа возвращаются stderr/exit code. SYSTEM-worker не устанавливается: выбран fallback из задания.

CMD/PS передают поток stdout/stderr и итог с taskId. Команды последовательные, максимум 3 минуты/128 КиБ. Kill нормализует excel.exe в excel и запрещает завершение самого помощника. Питание: shutdown.exe /r или /s /t 5 /f. Тесты не запускают питание и Kill пользовательских процессов.

## Сборка

```powershell
python -m pip install Pillow
python tools/generate_assets.py
dotnet build PixelHelper.csproj -c Release
dotnet run --project tests/PixelHelper.Tests.csproj -c Release
.\tools\build.ps1 -WixBin 'C:\Tools\wix314'
# Без MSI:
.\tools\build.ps1 -SkipMsi
```

SDK/Pillow/WiX нужны разработчику; MSI включает runtime. Генератор создаёт 10 прозрачных кадров 48×48 и Assets/preview.png. WiX 3.14.1, Product.wxs использует схему WiX 3. Скрипт собирает релиз в artifacts/release-VERSION; OutputDirectory позволяет задать каталог.

```powershell
msiexec /i PixelHelper.msi /qn /norestart SERVERURL="https://helper.example.org:5000"
msiexec /x PixelHelper.msi /qn /norestart
PixelHelper.exe --reset-user-data
```

Сброс текущего пользователя запускайте при закрытом помощнике. Полное удаление MSI чистит профили, upgrade пропускает очистку. Подробные инструкции GPO, роли и GLPI: `../LitleHelperServer/README.md`.

## Ограничения

Win32-регион строится по alpha ≥20, кнопки включаются, промежутки исключаются. GDI-регионы кэшируются. Окно 96×96 расширяется для меню до 500×400; после HWND_BOTTOM порядок корректируется перед shell-хостом значков, чтобы Explorer не закрыл робота целиком. Перекрытая анимация останавливается. DPI, Win+D, Explorer и клики по значкам требуют проверки на целевой Windows.

Диагностика: `PixelHelper.exe --diagnostics "C:\path\diagnostics.json"`, 5 секунд прогрева +30 измерения, без изменений реестра/координат. **Хаб в этом режиме не включается.** Старые замеры 1.0 не относятся к сетевому клиенту 1.1. Жёсткий бюджет 25–35 МБ RAM/CPU ≤0,1% не гарантируется: исходная WPF-версия его не выполнила, SignalR/WMI добавляют зависимости. Свежие функциональные результаты — `../VERIFICATION.md`.

## Сквозная проверка установленного сервера

`tests/Test-LiveClient.ps1 -ServerUrl http://172.16.16.61 -AccessFile artifacts/server-access.json -ClientExe artifacts/release-1.1.3/publish/PixelHelper.exe` проверяет реальный WPF-клиент: Online, инвентаризацию, безопасные CMD/PowerShell, аудит, обновление меню, Offline и повторный запуск. Используйте для первичной настройки свежего сервера с admin/admin123: тест меняет пароль администратора на случайный и сохраняет его только в локальном AccessFile, исключённом из Git. На уже настроенном сервере создайте AccessFile с полями serverUrl, username и password. Не запускайте второй экземпляр помощника одновременно. Тест сохраняет первоначальное разрешение удалённых команд и восстанавливает его в конце; адрес и ключ зарегистрированного ПК остаются настроенными.

## Автоматические обновления — 1.2.0

MSI устанавливает службу Windows PixelHelperUpdater под LocalSystem. Служба читает HKLM\Software\PixelHelper\ServerUrl, проверяет подписанный манифест с сервера через 30 секунд после старта и каждый час. Значение DWORD AutoUpdate=0 в этом разделе отключает обновления на конкретном ПК. На сервере SuperAdmin может приостановить выдачу обновлений всем клиентам.

Служба устанавливает только более новую версию после проверки RSA-подписи, размера и SHA-256. Файлы и журналы обновления находятся в %PROGRAMDATA%\PixelHelperUpdates с доступом SYSTEM/Administrators. Обновление сохраняет настройки и ключ клиента. Помощник закрывается на время обновления и запускается снова от прежнего пользователя; перезагрузка Windows автоматически не выполняется.

Для сборки подписанного релиза необходим PowerShell 7 и закрытый ключ artifacts/update-signing-key.pem, соответствующий UpdatePublicKey.pem. Сделайте защищённую резервную копию закрытого ключа; он исключён из Git. Не заменяйте публичный ключ между релизами без отдельного плана обновления доверия.

Скрипт tools/build.ps1 создаёт MSI и, при наличии ключа, PixelHelper.update.json. Отдельная подпись:

```powershell
.\tools\sign-update.ps1 -Msi .\artifacts\release-1.2.0\PixelHelper.msi
```

Загрузите пару MSI/JSON в раздел «Обновления клиента» панели. Для следующего релиза увеличьте Version в PixelHelper.csproj и Product.wxs. Клиентам без службы (1.1.3 и старше) нужен один начальный MSI, устанавливаемый администратором/GPO. Обычный перенос EXE из папки publish не устанавливает службу.

Установка вручную/SCCM и исправление адреса: [docs/CLIENT-INSTALLATION.md](../docs/CLIENT-INSTALLATION.md). Начиная с 1.2.2 новый клиент сам создаёт ключ и регистрируется. Адрес по умолчанию http://helper.gp1.loc, в установленном клиенте приоритет у 64-битного HKLM\Software\PixelHelper\ServerUrl. Кнопка отключения автозагрузки удалена. Для смены адреса администратор может выполнить tools/Set-ServerAddress.ps1.
