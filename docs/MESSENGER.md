# Внутренний мессенджер PixelHelper

Доступен начиная с клиента **1.2.11**, автоматический вход Windows — с **1.2.12**, группы и трей — с **1.2.13**, фирменные эмодзи — с **1.2.14**. Сервер настроен на `https://helper.gp1.loc` и хранит историю в PostgreSQL вместе с остальными данными Control Center.

## Начало работы

1. Войдите в Windows под своей доменной учётной записью. Дождитесь автоматического обновления помощника до 1.2.14 или установите соответствующий MSI. Служба проверяет обновления каждый час.
2. Нажмите помощника левой кнопкой и выберите **Мессенджер**.
3. Вход выполняется автоматически под пользователем, от которого запущен помощник. Логин и пароль вводить не нужно. Имя сотрудника появится в верхней части окна.
4. Выберите сотрудника слева. Поиск работает по отображаемому имени AD, логину и филиалу. Для одинаковых имён проверьте логин через поиск и филиал.
5. Напишите текст и нажмите **Отправить** или Enter. Shift+Enter добавляет перенос строки. Максимум — 4000 символов.

В каталоге отображаются активные AD-пользователи Control Center, включая сотрудников, впервые вошедших через окно мессенджера. Для появления нового сотрудника в списке ему достаточно один раз войти. Локальные учётные записи панели не включены. Обычные пользователи могут переписываться без административных прав.

Windows подтверждает личность с помощью Kerberos-билета для `HTTP/helper.gp1.loc`. Сервер проверяет билет, затем читает имя, objectGUID и состояние пользователя в AD через LDAPS. Пароль сотрудника не передаётся и не сохраняется. Сеанс мессенджера хранится только в памяти процесса, действует до 8 часов и автоматически обновляется через 6 часов. При запуске выполняется новый вход; файл сеанса прежней версии удаляется. При сетевой ошибке клиент повторяет попытку примерно раз в минуту. Кнопка **Обновить соединение** повторяет вход немедленно.

На общем компьютере каждый пользователь входит в Windows под своим AD-логином. Автозапуск запускает отдельного помощника в его сеансе. У каждого процесса собственная авторизация и история своего сотрудника; переключение пользователей Windows не меняет учётную запись уже работающего процесса. При выходе из Windows процесс завершится. Не запускайте помощника через «Запуск от имени другого пользователя»: тогда он использует учётную запись этого запуска. Локальный пользователь без доменной личности автоматически в мессенджер не войдёт.

Первый успешный вход сохраняет objectGUID AD в профиле. Переименование этой учётной записи сохраняет её внутренний ID и историю. Новая AD-учётная запись с прежним логином и другим objectGUID не получает чужую историю; в этом случае требуется разбор профилей администратором.

## История и уведомления

Сообщение сначала сохраняется на сервере, затем доставляется через SignalR. Статус **Сохранено** означает, что оно записано в базу; **Прочитано** — что получатель открыл активное окно соответствующего диалога. Закрытый мессенджер продолжает получать сообщения через работающий помощник.

Получатель Offline увидит историю и непрочитанные сообщения после подключения. Клиент переподключается и обновляет состояние; повторная отправка неизменённого текста после сетевой ошибки использует прежний идентификатор, чтобы не создать дубликат. Если отправка не прошла, текст остаётся в поле. Не закрывайте окно до повторной попытки, если хотите сохранить черновик.

Последние 50 сообщений загружаются при открытии диалога. Кнопка **Предыдущие сообщения** загружает более ранние записи. История и прочтение синхронизируются между компьютерами, где сотрудник вошёл в мессенджер.

В облачке над помощником появляются имя отправителя, число непрочитанных сообщений и короткий текст. **Открыть переписку** переводит в нужный диалог. Несколько быстро пришедших сообщений объединяются. Для открытого активного диалога отдельное облачко и звук не нужны.

В верхней части окна можно независимо отключить **Звук**, **Текст уведомления**, **Уведомления Windows**, **Облачко** или включить **Не беспокоить**. На заблокированном рабочем столе уведомления и звук не показываются. Значок непрочитанных сообщений обновляется даже при отключённых уведомлениях. Звук уведомления Windows зависит от системных настроек; когда уведомления Windows отключены, клиент использует системный звук Asterisk.

## Трей и отображение помощника

Значок робота находится в трее Windows; при наличии непрочитанных сообщений на нём появляется оранжевая отметка. Если значок скрыт системой, откройте стрелку скрытых значков и закрепите PixelHelper в области уведомлений через настройки Windows.

Щелчок по значку открывает мессенджер. Правый щелчок открывает меню:

- **Поверх всех окон** — робот виден над обычными приложениями.
- **Обычный режим** — робот ведёт себя как обычное окно, его могут перекрывать приложения.
- **Фон · под окнами** — робот остаётся на рабочем столе под окнами приложений; это прежний режим по умолчанию.
- **Скрыть / Показать помощника** — скрывает только робота; мессенджер, связь с сервером и уведомления продолжают работать.
- **Не беспокоить** — отключает всплывающие уведомления и звук.
- **Выход** — завершает клиент целиком.

Режим и скрытие сохраняются отдельно в профиле каждого пользователя Windows. После обновления или следующего входа в Windows они восстанавливаются. Меню отображения также доступно правым щелчком по роботу.

Уведомление Windows показывает название чата и количество новых сообщений; текст включается настройкой **Текст уведомления**. Щелчок открывает соответствующий чат. Если сообщения пришли одновременно в несколько чатов, клиент объединяет их в одно уведомление, открывающее мессенджер. Windows может скрывать уведомления в режиме фокусировки или при системном запрете уведомлений.

## Список чатов и группы

Личные и групповые чаты находятся в одном списке. Чаты с непрочитанными сообщениями идут первыми, внутри этой категории — по времени последнего сообщения. Остальные также сортируются по последнему сообщению. Синий счётчик показывает количество непрочитанных сообщений; у группы есть значок участников. Ниже имени видны последнее сообщение и время. Для групп в сообщениях отображаются имена авторов из AD.

Нажмите **Создать группу**, введите название (до 80 символов), выберите сотрудников (Ctrl / Shift для нескольких) и нажмите **Создать**. В группе может быть от 2 до 100 участников, включая создателя. Рядом с именем в выборе участников указан AD-логин, чтобы различать одинаковые имена.

Откройте групповой чат и нажмите **Участники группы**. Создателю доступны изменение названия, приглашение сотрудника, удаление участника, передача владения и закрытие группы. Остальным доступен просмотр состава и выход. Права проверяются сервером. После передачи владения управлять группой может новый владелец; прежний становится обычным участником.

Новый участник видит историю с момента приглашения. Удалённый или вышедший теряет доступ к группе; при повторном приглашении старая история не открывается. Перед выходом создатель должен передать владение, если в группе остаются другие участники. Закрытие группы прекращает отправку и изменение состава, но сохраняет доступную участникам историю. Закрытую группу можно покинуть.

Непрочитанные сообщения и отметки прочтения группы учитываются отдельно для каждого участника и синхронизируются между его компьютерами. Для групп не показывается общий статус «прочитано всеми»: собственные сообщения имеют статус **Сохранено**. Правила хранения истории в Control Center распространяются и на группы.

## Эмодзи помощника

Нажмите **Эмодзи** слева от поля сообщения и выберите эмоцию. Код вставляется в позицию курсора, заменяя выделенный текст; под полем появляется предпросмотр. При выборе помощник выполняет соответствующую анимацию. В отправленных сообщениях и истории код отображается изображением пиксельного робота. Наведение на изображение показывает название эмоции.

| Название | Код | Реакция |
|---|---|---|
| Привет | `:helper_wave:` | Машет рукой |
| Радость | `:helper_joy:` | Улыбается и подпрыгивает |
| Спасибо | `:helper_thanks:` | Поднимает большой палец, показывает галочку |
| Грусть | `:helper_sad:` | Грустные глаза и слеза |
| Удивление | `:helper_surprise:` | Расширяет глаза, поднимает антенну |
| Смех | `:helper_laugh:` | Смеётся с покачиванием |
| Сон | `:helper_sleep:` | Закрывает глаза, появляются Z |
| Думаю | `:helper_think:` | Подносит руку к лицу, показывает вопрос |
| Праздник | `:helper_party:` | Радуется с пиксельными искрами |
| Головокружение | `:helper_dizzy:` | Вращающиеся глаза и звёздочки |

Коды можно написать вручную или вставить вместе с текстом. Анимация при вставке запускается выбором в панели; ручное редактирование текста и открытие истории реакции не вызывают. Обычные Unicode-эмодзи продолжают отображаться как текст и не запускают анимации. В старых клиентах фирменные эмодзи отображаются текстовыми кодами.

При получении нового личного или группового сообщения помощник адресата повторяет первые три фирменных эмодзи последовательно. Его собственное отправленное сообщение не запускает повторную реакцию после подтверждения сервера. Очередь ограничена девятью реакциями, отложенные реакции старше 30 секунд пропускаются. Перетаскивание, отправка заявки и важные уведомления имеют приоритет; после эмоции помощник возвращается к покою или прежнему сну.

В верхней части мессенджера доступны **Реакции эмодзи** (все реакции) и **Входящие реакции** (только полученные сообщения). Настройки сохраняются в профиле Windows. Скрытый помощник, заблокированный рабочий стол и **Не беспокоить** подавляют анимации. Для защиты от повторной доставки последние 256 обработанных сообщений с эмодзи учитываются отдельно для сервера и пользователя AD в `%APPDATA%\PixelHelper\emoji-seen.json`; содержимое сообщений и пароли в этот файл не записываются.

Сервер хранит исходные текстовые коды в существующей истории; новая миграция базы для эмодзи не требуется. В уведомлениях и кратком списке чатов они заменяются названиями эмоций, например `[Привет]`.

**Online** в мессенджере означает наличие подключённого сеанса мессенджера сотрудника; это отдельный статус от Online компьютера в Control Center.

## Настройки администратора

В веб-панели откройте **Мессенджер**. Доступ требует права `settings.manage` (у супер администратора оно есть по умолчанию).

- **Включить личную переписку** — разрешает или отключает работу мессенджера. При отключении его текущие соединения завершаются; история сохраняется.
- **Срок хранения сообщений** — 0 означает хранение без ограничения (значение по умолчанию). Можно задать от 30 до 3650 дней. При ежедневной очистке более старые сообщения удаляются; перед сохранением ненулевого срока панель запрашивает подтверждение.
- **Сохранено сообщений** — общее количество записей без раскрытия содержимого.

Содержание диалога через API доступно только его участникам, включая пользователей с административными ролями. Веб-панель не предоставляет просмотр чужой переписки. Данные хранятся в серверной базе; ограничения API не заменяют контроль административного доступа к самой базе и её резервным копиям.

Отключение учётной записи в разделе **Пользователи** прекращает её доступ. Переписка с отключённым сотрудником сохраняется в списке существующих диалогов, но отправка ему новых сообщений запрещена.

## Проверки и ограничения первого выпуска

Проверены сохранение и доставка через настоящий SignalR, работа с Offline-получателем, история и пагинация, непрочитанные сообщения, подтверждение прочтения, отсутствие дубликатов, изоляция третьего пользователя, отключение аккаунта, переименование AD и защита истории от повторного использования логина. Интерфейс входа и диалога проверен через WPF; миграция PostgreSQL выполнена на сервере после резервного копирования.

Поддерживаются личные и групповые текстовые диалоги. Файлы и редактирование сообщений пока не реализованы. Черновики не сохраняются после закрытия окна. Реальный Kerberos-вход и обновление сеанса проверены под zqrey3; права групп, границы истории, доставка SignalR и счётчики проверены автоматическими тестами. Нативный значок трея, скрытие/восстановление робота и список чатов проверены на Windows. Практическую проверку переключения Windows на общем компьютере выполните входом двух сотрудников.

Группы добавлены отдельными таблицами, личная история не переписывалась. Перед обновлением сервера сохранена резервная копия PostgreSQL. Текущая реализация рассчитана на один экземпляр серверного приложения в Docker Compose; для нескольких реплик потребуется распределённая синхронизация изменения состава групп.

## Требования для автоматического входа

- Компьютер состоит в AD, пользователь вошёл под доменным логином и имеет доступ к контроллеру домена. При входе по сохранённым данным вне сети авторизация выполнится после восстановления доступа к AD.
- Адрес клиента — `http://helper.gp1.loc` или `https://helper.gp1.loc`; мессенджер всегда использует HTTPS. Адрес по IP не подходит для Kerberos. Сертификат helper должен быть доверенным на компьютере.
- Время клиента, сервера и контроллера синхронизировано. Допустимое расхождение Kerberos обычно до 5 минут.
- В Control Center включён AD. Для проверки состояния пользователей используются уже сохранённые логин/пароль чтения каталога в настройках Telegram (`litlehelper`); их права — чтение AD. Включать Telegram-уведомления для автовхода не требуется.
- Настройки браузера/GPO для автоматического входа в сайты не требуются: помощник сам использует текущие Windows credentials.

На `dc01.gp1.loc` создана отдельная непривилегированная служебная учётная запись **LHMessengerSSO** со SPN `HTTP/helper.gp1.loc`, шифрованием AES256, запретом делегирования и неистекающим случайным паролем. Это учётная запись службы, а не сотрудника. Не меняйте её пароль отдельно от keytab.

Keytab находится в защищённой папке `C:\ProgramData\HelperMessengerKerberos` на dc01 и в постоянном Docker volume `server-data`, путь `/app/data/kerberos/helper.keytab` на сервере. Папка контейнера имеет права 700, keytab — 600, владелец app (UID 1654). Файл `/app/data/kerberos/krb5.conf` содержит настройки домена; образ устанавливает системную библиотеку Kerberos. После первичной настройки обычный `docker compose up -d --build` сохраняет SSO. При переносе восстановите защищённый volume и DNS, не помещайте keytab в Git.

Проверка на доменном компьютере: `klist get HTTP/helper.gp1.loc`. Если билет не выдаётся, проверьте DNS, связь с DC, время и уникальность SPN. Если билет есть, но автовход не работает, проверьте соответствие keytab паролю службы и параметры чтения AD. Сервер принимает только Kerberos; подмена имени через заголовки и переход на NTLM не разрешены.

### Оформление и анимация (клиент 1.2.15)

Откройте «Оформление и уведомления» в верхней части мессенджера.
Выберите тему: «Помощник» (по умолчанию), светлая, тёмная или высококонтрастная.
Размер текста: маленький, обычный, крупный или очень крупный; он применяется к списку чатов, сообщениям и полю ввода.
Фон: однотонный, точки, сетка либо локальное изображение PNG/JPEG/BMP. Для изображения можно настроить затемнение. Изображение не передаётся на сервер; при его удалении используется обычный фон.
Нажмите «Применить»: оформление меняется сразу и сохраняется для текущего пользователя Windows.

Фирменные эмодзи анимируются в сообщениях, меню выбора и предпросмотре. Настройка «Анимация эмодзи в переписке» отключает их движение отдельно от реакций помощника. Невидимые эмодзи и свёрнутое окно не меняют кадры; при удалении элементов таймеры освобождаются.

### Повторное подключение (1.2.16)
Если исчезла кнопка отправки заявки или перестали приходить сообщения, нажмите правой кнопкой на значок помощника в трее и выберите «Повторить подключение». Клиент пересоздаст соединение с сервером и повторит автоматический вход Windows в мессенджер. Перезапуск приложения не требуется. При недоступном сервере автоматические попытки подключения продолжатся.


### Файлы и изображения (клиент 1.2.17)

Кнопка скрепки рядом с полем ввода прикрепляет файлы любых расширений. Можно выбрать до 10 файлов: до 50 МБ каждый и до 100 МБ всего на сообщение. Нажмите имя вложения с крестиком, чтобы убрать его перед отправкой. Вложения можно отправить с текстом либо без текста.

Для отправки скриншота или изображения скопируйте его и нажмите Ctrl+V в поле сообщения. Изображение добавится как PNG-вложение; обычный текст вставляется как прежде. Файлы, скопированные из Проводника, также можно вставить через Ctrl+V.

Нажмите на файл в сообщении, чтобы выбрать место скачивания. Нажмите на изображение, чтобы открыть просмотр, затем «Скачать изображение», чтобы сохранить оригинал. Для форматов изображений, которые не поддерживает Windows, доступно скачивание файла. Файлы не запускаются автоматически.

Вложения доступны только участникам соответствующей переписки. Новые участники группы не получают файлы из сообщений до вступления; исключённые участники теряют доступ. При удалении истории по сроку хранения удаляются и вложения. Данные файлов хранятся в серверном томе server-data, в data/chat-files; для полного резервного копирования нужны и база PostgreSQL, и том server-data.

Зелёный кружок перед именем контакта означает активное соединение с мессенджером, серый — отсутствие соединения. Это состояние мессенджера, а не только подключения компьютера к сети. У групп кружок присутствия не показывается.
