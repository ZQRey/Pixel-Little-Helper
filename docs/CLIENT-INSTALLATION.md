# Установка и настройка PixelHelper: вручную и через SCCM

## Адрес подключения

В вашей сети используйте **`http://helper.gp1.loc`**. Проверено 6 октября 2026 года: DNS указывает на `172.16.16.61`, `/health` отвечает `ok`. Внешний порт сервера — 80, поэтому `:5000` добавлять не нужно.

Допустимый запасной адрес: `http://172.16.16.61`. Используются **прямые слеши `/`**, без запятой, пробелов и кавычек в поле мастера. `http:\\172.16.16.61,` — неправильный адрес. HTTPS указывайте только после настройки HTTPS на сервере; сейчас рабочий адрес начинается с `http://`.

DNS-имя предпочтительнее IP: если IP сервера изменится, достаточно обновить DNS-запись `helper.gp1.loc`, сохранив прежнее имя и данные сервера.

## Автоматическая регистрация

Начиная с **1.2.2**, клиент сам создаёт случайный ключ из 48 криптографически случайных байт, сохраняет его в `%APPDATA%\PixelHelper\config.json` и отправляет на сервер. Новый ПК появляется в Control Center автоматически. Вручную создавать запись ПК и выдавать ключ при новой установке не требуется. Регистрация выполняется после запуска GUI в пользовательском сеансе, а не при копировании MSI.

Сервер хранит только SHA-256 ключа. Повторная регистрация с тем же именем ПК и ключом допустима; попытка заменить ключ уже зарегистрированного ПК возвращает 409. Ключ нельзя переносить на другой ПК. Права доступа к панели регистрация не выдаёт. Endpoint регистрации доступен по сети без учётной записи панели; не публикуйте Control Center в Интернет без отдельного ограничения сетевого доступа.

Существующий ключ сохраняется при обновлении. Если файл конфигурации потерян, а имя ПК уже есть на сервере, новый случайный ключ не сможет заменить прежний автоматически. Администратор должен выдать новый ключ через «Компьютеры → Подключить ПК» при отключённом клиенте и записать его в конфигурацию, либо удалить устаревшую Offline-запись перед новой регистрацией.

Ключ хранится в пользовательском профиле. На общем ПК для второго пользователя используйте тот же ключ этого ПК в его профиле; отдельный новый ключ для существующего имени будет отвергнут. Не распространяйте один готовый config.json с ключом на разные компьютеры.

## Ручная установка

1. Возьмите актуальный `PixelHelper.msi`. Для изменений из этой инструкции подготовлен релиз **1.2.2**, файл `LitleHelperClient/artifacts/release-1.2.2/PixelHelper.msi`.
2. Закройте ранее запущенный помощник. Запустите MSI, подтвердите UAC учётной записью **локального администратора**. Права администратора AD не требуются.
3. В поле адреса введите `http://helper.gp1.loc` и завершите установку.
4. Войдите в сеанс сотрудника. Ручная настройка ключа для нового ПК не требуется; он будет создан при запуске помощника.
5. Помощник запустится автоматически в вашем сеансе и покажет приветствие. Начиная с 1.2.10 подтверждать автозагрузку не нужно.
6. Убедитесь, что компьютер появился Online в Control Center.

Установленные файлы: `C:\Program Files\PixelHelper`. Служба `PixelHelperUpdater` занимается только обновлениями; сам помощник работает в интерактивном пользовательском сеансе.

### Ручная настройка ключа для восстановления существующего ПК

Закройте помощника. Откройте `%APPDATA%\PixelHelper\config.json`. Если файла нет, создайте папку и файл, используя пример ниже. Существующий файл редактируйте с сохранением остальных полей:

```json
{
  "serverUrl": "http://helper.gp1.loc",
  "hubUrl": null,
  "clientToken": "ИНДИВИДУАЛЬНЫЙ_КЛЮЧ_ЭТОГО_ПК",
  "enableAdministrativeCommands": true,
  "allowRemoteCommands": false
}
```

`hubUrl: null` означает, что адрес SignalR будет автоматически получен как `http://helper.gp1.loc/helperHub`. Если ранее задан явный адрес `hubUrl`, он имеет приоритет для подключения хаба и должен быть исправлен отдельно.

Сохраните корректный JSON и запустите помощника. Ключ хранится в пользовательском профиле; на общем компьютере его нужно настроить для каждого пользователя, запускающего помощника. Один и тот же ключ этого ПК можно использовать в разных профилях этого ПК, но нельзя переносить на другие компьютеры.

## Тихая установка из командной строки

В командной строке с административными правами, из папки с MSI:

```bat
msiexec.exe /i "PixelHelper.msi" /qn /norestart REBOOT=ReallySuppress SERVERURL="http://helper.gp1.loc" /L*v "C:\Windows\Temp\PixelHelper-install.log"
```

Параметр пишется именно **`SERVERURL`**, прописными буквами. `/qn` отключает интерфейс установки. Это устанавливает программу и службу, задаёт адрес всем пользователям, ключ автоматически создаётся и отправляется на сервер при запуске GUI в пользовательском сеансе.

Коды завершения MSI: `0` — успех, `3010` — успех с требованием перезагрузки, `1618` — другая установка уже выполняется. Подробности — в указанном журнале.

## Установка через SCCM / Microsoft Configuration Manager

1. Создайте папку источника, например `\\SCCM\Sources\PixelHelper\1.2.2`, и скопируйте туда MSI. Не помещайте в неё приватный ключ подписи обновлений или файлы с паролями панели.
2. В консоли откройте **Software Library → Application Management → Applications → Create Application**.
3. Выберите автоматическое чтение сведений из **Windows Installer (*.msi)**, укажите UNC-путь к MSI.
4. В Deployment Type задайте команду установки из предыдущего раздела.
5. В **User Experience** выберите:
   - **Install for system**;
   - **Whether or not a user is logged on**;
   - видимость установки **Hidden**.
6. В Requirements ограничьте установку поддерживаемыми 64-битными Windows. Настройте коды `0` — Success, `3010` — Soft Reboot, `1618` — Fast Retry, если они ещё не заданы стандартными настройками.
7. Замените автоматически созданное обнаружение по точному MSI ProductCode на проверку версии файла, описанную ниже. При автообновлении Major Upgrade ProductCode меняется, и SCCM не должен пытаться снова поставить старый MSI.
8. Выполните **Distribute Content**, выберите Distribution Points.
9. Сначала разверните на тестовую коллекцию устройств. Проверьте установку, службу, ключ и Online. После этого разверните на рабочую коллекцию: **Purpose → Required** либо **Available**, согласно вашей политике.

### Detection Method с учётом автообновления

Выберите **Use a custom script**, язык PowerShell. Не включайте выполнение этого скрипта как 32-битного процесса на 64-битных клиентах.

```powershell
$exe = Join-Path $env:ProgramW6432 'PixelHelper\PixelHelper.exe'
if (Test-Path -LiteralPath $exe) {
    $version = [version]([Diagnostics.FileVersionInfo]::GetVersionInfo($exe).FileVersion)
    if ($version -ge [version]'1.2.10.0' -and
        (Get-Service PixelHelperUpdater -ErrorAction SilentlyContinue)) {
        Write-Output 'Installed'
    }
}
```

При обновлении исходного пакета повышайте минимальную версию в скрипте. Более новая установленная версия тоже считается установленной. Проверяется наличие службы, а не состояние Running: временная остановка службы не должна приводить к повторной установке.

### Автоматическая регистрация и автозагрузка при SCCM

Начиная с **1.2.10**, MSI сам создаёт запись `PixelHelper` в 64-битном `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Run`. Дополнительная GPO для автозапуска и флаг FirstRunCompleted больше не нужны. Старую GPO, которая устанавливает другую команду запуска, отключите, чтобы она не перезаписывала настройку MSI.

Служба PixelHelperUpdater автоматически запускает GUI с обычным токеном вошедшего пользователя, включая тихую установку от SYSTEM через SCCM. При нескольких активных сеансах запуск выполняется в каждом. Если никто не вошёл, помощник появится после входа. При обычной работе закрытый пользователем помощник не открывается службой каждые 15 секунд; следующий вход или перезапуск службы запускает его снова. Повторный запуск в одном сеансе подавляется mutex приложения.

При запуске показывается приветствие с отображаемым именем AD или полным именем локальной учётной записи. Если Windows не может получить имя, выводится «Здравствуйте!» без логина. Вопрос «оставить помощника» отсутствует. Дополнительные пароли AD или права администратора для запуска не требуются.

Ключ создаётся в профиле сотрудника, а не SYSTEM. На общем ПК заранее обеспечьте одинаковый существующий ключ этого ПК в профилях сотрудников: сейчас регистрация привязана к имени компьютера и разные автоматически созданные ключи разных профилей приведут к отказу регистрации. Не копируйте ключ между разными ПК. При переустановке сохраняйте config.json.

Проверка пилотной установки:
1. На ПК со вошедшим сотрудником выполните установку через SCCM с параметрами выше. Помощник должен появиться без выхода из Windows и без вопроса об автозагрузке.
2. Проверьте службу PixelHelperUpdater (Running, Automatic), запись HKLM Run и версию клиента 1.2.10 или новее.
3. В Control Center проверьте Online и создание заявки с тестового ПК.
4. Перезайдите в Windows: помощник должен запуститься автоматически и приветствовать по имени.
5. На ПК без вошедшего пользователя установите пакет, затем войдите под обычной учётной записью и повторите проверку.
6. Если GUI отсутствует, проверьте политики Windows, Startup Apps и защитное ПО: они могут блокировать автозапуск. Проверьте DNS helper.gp1.loc и доступ к HTTP порту 80.
Журналы SCCM на клиенте: `C:\Windows\CCM\Logs\AppEnforce.log`, `AppDiscovery.log`, `CAS.log`, `ContentTransferManager.log`. Журнал MSI — `C:\Windows\Temp\PixelHelper-install.log`.

### Удаление через SCCM после автообновлений

Команду удаления привязывайте к **текущему** MSI ProductCode из 64-битного `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall` (DisplayName `PixelHelper`, Publisher `PixelHelper`), а не навсегда к GUID первоначального пакета. Для выбранного текущего GUID команда имеет вид:

```bat
msiexec.exe /x "{ТЕКУЩИЙ-PRODUCT-CODE}" /qn /norestart
```

Если требуются централизованные удаления после автообновлений, задайте отдельный uninstall-скрипт, который находит текущую запись перед вызовом MSI. Не используйте `Win32_Product`: его запрос может запускать проверки и восстановление других MSI. Удаление помощника очищает его пользовательские настройки.

## Исправление неверного адреса или смена имени сервера

**При установленном MSI приоритет имеет 64-битный HKLM**, а не `serverUrl` в пользовательском JSON:

```text
HKEY_LOCAL_MACHINE\SOFTWARE\PixelHelper
ServerUrl (REG_SZ) = http://helper.gp1.loc
```

Изменение только JSON не исправит установленный в MSI машинный адрес, если в реестре остаётся другое допустимое значение. Служба обновлений также читает этот HKLM.

### Готовый скрипт

В PowerShell с административными правами выполните из папки репозитория:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\LitleHelperClient\tools\Set-ServerAddress.ps1" -ServerUrl "http://helper.gp1.loc"
```

Скрипт явно открывает 64-битный реестр, проверяет синтаксис адреса, записывает `ServerUrl` и перезапускает службу обновления. Программу и данные он не удаляет. Скрипт также можно развернуть через SCCM от SYSTEM. Перезапустите GUI помощника отдельно в пользовательском сеансе.

Если `hubUrl` задан явно, закройте GUI и установите `"hubUrl": null` в `%APPDATA%\PixelHelper\config.json` каждого затронутого пользователя. Сохраните `clientToken`, координаты и остальные настройки. Для переносной версии без MSI меняйте `serverUrl` в этом JSON; при наличии машинной установки её HKLM всё равно имеет приоритет.

### Через редактор реестра / GPO

1. Закройте GUI помощника.
2. Откройте regedit с правами администратора и измените `ServerUrl` по указанному пути. На x64 используйте обычный `SOFTWARE\PixelHelper`, а не `SOFTWARE\WOW6432Node\PixelHelper`.
3. Перезапустите службу `PixelHelperUpdater` через services.msc.
4. При необходимости очистите старый `hubUrl` в пользовательском JSON.
5. Запустите помощника в сеансе сотрудника и проверьте Online.

Для массовой смены адреса можно распространить тот же REG_SZ через **Computer Configuration → Preferences → Windows Settings → Registry**, действие Update.

Если меняется только IP за прежним DNS-именем, клиентскую конфигурацию менять не нужно. После изменения DNS дождитесь обновления кеша или выполните `ipconfig /flushdns`, затем перезапустите помощника и службу. Ключи остаются действительными, если используется прежняя база Control Center. На новом сервере с новой базой потребуется повторная регистрация ПК.

## Проверка связи

```powershell
Resolve-DnsName helper.gp1.loc
Test-NetConnection helper.gp1.loc -Port 80
Invoke-RestMethod 'http://helper.gp1.loc/health'
Get-Service PixelHelperUpdater
```

Если health отвечает, а ПК Offline: проверьте индивидуальный ключ, совпадение имени ПК, старый `hubUrl`, запуск GUI и `%APPDATA%\PixelHelper\error.log`. Само наличие службы обновления не означает, что GUI подключён к серверу.

## Автообновление и меню

После первоначальной административной установки подписанные обновления выполняются службой SYSTEM без UAC. Проверка — каждые 60 минут, первая — примерно через 30 секунд после запуска службы. Релиз 1.2.2 удаляет кнопку отключения автозагрузки из подключённого и автономного меню. Возможность закрыть помощника сохранена.
