# Windows и веб-мессенджер — выпуск 1.2.19

Адрес: **https://helper.gp1.loc/messenger/**. Это отдельный интерфейс мессенджера на том же сервере; Control Center остаётся на главной странице.

## Что реализовано

- Общие пользователи AD, переписки, группы, история и вложения между Windows и веб.
- Единый файл палитр и размеров `LitleHelperServer/wwwroot/messenger/design-tokens.json`; Windows встраивает этот файл в сборку.
- Windows: собственная рамка окна, четыре зоны, градиент исходящих сообщений, компактные контакты и кнопки, тёмная/светлая/контрастная темы. Emoji и реакции помощника сохранены.
- Веб: адаптивная SPA, стеклянные поверхности, темы, размер текста, DND, непрочитанные, онлайн, подключение через SignalR и восстановление после обрыва.
- Закрепление, избранные диалоги и отключение уведомлений сохраняются на сервере отдельно для каждого пользователя и синхронизируются между интерфейсами.
- Реакции на сообщения: правый клик по сообщению. Повтор той же реакции снимает её. Один пользователь ставит одну реакцию на сообщение.
- Поиск по доступной серверной истории: кнопка поиска, фраза от двух символов. До 50 результатов на запрос. Временное отключение/дата вступления в группу учитываются.
- «Печатает…»: события без хранения каждого нажатия в базе, ограничение частоты и исчезновение через пять секунд.
- Состояние отправки сразу видно в ленте; ошибка позволяет повторить с тем же clientId без дубликатов.

## Вход

1. Откройте HTTPS-адрес. HTTP не используется для входа и сессии.
2. Нажмите «Войти под пользователем Windows». На доменном компьютере браузеру должен быть разрешён Kerberos для `helper.gp1.loc`.
3. Если автовход не настроен или не завершился, используйте форму с логином и паролем AD. Пароль не сохраняется приложением.

Существующие настройки браузеров для `glpi.gp1.loc` не обязательно охватывают `helper.gp1.loc`: включите helper в тот же список доверенных адресов для интегрированной авторизации. Для Firefox добавьте host в `network.negotiate-auth.trusted-uris` через корпоративную политику; настройки делегирования не нужны для обычного подтверждения пользователя самим сервером мессенджера.

Браузер получает отдельную ограниченную cookie-сессию Secure/HttpOnly/SameSite=Strict на восемь часов. Токен и пароль не записываются в localStorage. В localStorage находятся только оформление, размер текста и DND. Для изменения данных применяется заголовок защиты от CSRF и проверка Origin. Десктоп сохраняет существующий bearer-поток AD SSO.

По истечении сессии войдите повторно. Кнопка «Выйти» находится в настройках веб-мессенджера. Автоматический вход Windows-клиента по-прежнему использует текущего пользователя Windows.

## Использование

- Категории в Dock: все, личные, группы, непрочитанные, избранные.
- Правый клик по диалогу: закрепить, добавить в избранное, отключить уведомления; у личного контакта — приглашение в свою группу.
- Информация о чате: профиль и участники. Владелец может пригласить сотрудника, переименовать/закрыть группу, удалить или временно отключить участника через правый клик.
- Скрепка/плюс прикрепляет файлы любых расширений; Ctrl+V вставляет скопированное изображение. Лимит: 10 файлов, 50 МБ каждый, 100 МБ всего.
- Изображение открывается по клику, файл скачивается с исходным именем. Доступ проверяется сервером.
- Enter — отправить, Shift+Enter — новая строка. Во время ввода через IME Enter не отправляет незавершённый текст.
- Уведомления браузера включаются явно в настройках. Для работы приложение должно оставаться открытым; уведомления после полного закрытия браузера этим выпуском не реализованы.
- Веб-рассылка доступна в настройках пользователю с правом `chat.broadcast`: всем либо онлайн, обычная/срочная. Веб-форма этого выпуска отправляет текст; рассылка файлов и отчёт остаются доступны в Windows.
- Веб-галерея вложений сейчас отображает загруженную страницу/историю. Полный отдельный индекс медиа и ссылки ещё требуют следующего этапа.

## Установка и сервер

Веб-ресурсы публикуются ASP.NET Core и входят в существующую сборку Docker. Запуск: `docker compose up -d --build`. Отдельные сервисы frontend и Node.js на сервере не требуются.

Новые таблицы ChatPreferences и ChatReactions создаются автоматически, существующая история и ключи компьютеров сохраняются. Перед выпуском сохранены база и изменённые исходники в `/home/zqrey/backups/helper-pre-web-20261007.*`.

Windows распространяется подписанным MSI/обновлением 1.2.19 по существующей схеме службы обновления. Версия 1.2.18 совместима с новым сервером, но не показывает новые реакции и настройки диалогов.

## Проверки

Проверены SQLite и PostgreSQL: AD cookie, CSRF, запрет cross-origin и HTTP, изоляция настроек, реакции и запрет стороннему пользователю, поиск и отсутствие доступа к чужой истории, прежние группы/файлы/рассылки. Windows-тесты проверяют четыре зоны, темы/крупный текст, emoji, вложения и вставку изображения.

Реальный Kerberos-вход текущего пользователя на сервер вернул HTTP 200. Браузер Edge с этой сессией проверил каталог, SignalR, историю/информацию группы, мобильную навигацию и настройки без JavaScript-исключений. Автоматический challenge в headless-браузере не завершился; интерактивный автовход зависит от корпоративных настроек браузера. Отправки сотрудникам и изменения состава реальных групп при проверке не выполнялись.

## Следующие этапы исходного плана

Этот выпуск реализует новый интерфейс, рабочую веб-версию и часть общих функций. Ответы с адресуемыми цитатами, полный индекс медиа, голосовые сообщения/waveform, GIF, опросы, каналы, аудио/видеозвонки и персональная блокировка пока не реализованы. Для них нужны отдельные модели/контракты и проверки из MESSENGER-REDESIGN-PLAN.md; декоративных кнопок, имитирующих эти действия, в интерфейсе нет.
