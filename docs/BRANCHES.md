# Филиалы, кабинеты и исполнители заявок

Клиент 1.2.6 добавляет выбор филиала и кабинет в форму «Написать программистам». После успешной отправки он запоминает выбранные значения для следующей заявки. Филиалы загружаются с сервера при открытии формы. Если список недоступен, отправка блокируется с объяснением ошибки.

В Control Center откройте **Филиалы**. Пользователь с правом управления настройками может добавлять, переименовывать и отключать филиалы. Неиспользуемый филиал можно удалить; если на него ссылаются пользователи или заявки, вместо удаления отключите его. Отключение запрещает создание новых заявок, сохраняя историю. Название филиала в существующей заявке остаётся таким, каким было при отправке.

В **Пользователи → Изменить** выберите филиал каждого администратора/оператора. Изменение профиля отзывает старый сеанс панели. SuperAdmin имеет доступ ко всем филиалам, независимо от выбранного филиала в профиле. Администраторы и операторы видят и обрабатывают заявки своего филиала; обычный пользователь видит только собственные заявки. Индивидуальные права управления заявками по-прежнему необходимы: филиал сам по себе не выдаёт права.

В разделе **Заявки** есть фильтр филиалов вместе с фильтром статусов. Филиал и кабинет показаны в списке и карточке. Сервер проверяет доступ также при обращении к карточке и изменении статуса по прямому URL.

Telegram отправляет уведомление о новой заявке **один раз в общую настроенную группу**, где его видят участники группы. Нажатие `/start` несколькими администраторами не включает рассылку новых заявок каждому из них. В уведомлении указаны филиал и кабинет. Принять заявку может сотрудник соответствующего филиала либо SuperAdmin; при одновременном принятии выигрывает один исполнитель. После принятия личная карточка отправляется принявшему сотруднику, а `/my` показывает назначенные ему активные заявки с учётом филиала. Изменение филиала профиля применяется при следующем действии бота.

Филиал и кабинет также добавляются в текст обращения GLPI. Это справочник Control Center: он не меняет сущности, группы и профили GLPI. Права API и доступность исполнителя в GLPI должны быть настроены отдельно.

Старые заявки сохраняются как **Без филиала**. Они доступны сотрудникам с правом просмотра всех заявок и прежними правами управления. Когда существует хотя бы один активный филиал, новые заявки требуют филиал и кабинет. Обновите клиентов до 1.2.6: старый клиент не отправляет эти поля и получит объяснение о необходимости обновления.
