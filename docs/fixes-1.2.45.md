# Исправления по аудиту от 12.10.2026

Состояние: исправления реализованы в исходниках, подготовлены клиент 1.2.45, подписанный манифест и совместимый серверный пакет. Рабочие Helper и AudioRONGTA в рамках исправлений ещё не менялись; автообновление 1.2.45 не опубликовано.

## Что изменено

| Аудит | Реализация |
| --- | --- |
| F01, F09 | Смена своего пароля AD подтверждается текущим паролем. LDAP bind выполняется от пользователя, unicodePwd изменяется Delete/Add, привилегированный Replace от сервисной записи удалён. Добавлены аудит, ограничение частоты, оба заголовка агента и HTTPS. Пароли вводятся в PasswordBox и не записываются в историю помощника. |
| F02 | Принятие и сброс Белого кода требуют отдельного права emergency.manage. Действия протоколируются. Экран отправляет Bearer, вход возвращает на экран в той же вкладке без токена в URL. |
| F03 | Закрытие окна на ПК стало локальным действием. Серверный отбой требует отдельного права, учитывает филиал и ID события, ставит внешнюю отмену в очередь. Диспетчер AudioRONGTA проверяет свой ID под блокировкой линии. |
| F04 | Привязка пользователя требует проверенной HTTPS-сессии мессенджера и ключа конкретного соединения агента. Заявленный логин больше не предоставляет роль администратора. Адресные группы используют проверенную привязку. Неподтверждённые авторы заявок отмечаются как unverified:<ПК>, без подмены доменного автора по ФИО. |
| F05 | Контракт подтверждения содержит три аргумента. Вызовы имеют сохраняемый локальный ID и настоящий внешний ID AudioRONGTA. Случайные ID удалены. Подтверждение проверяет получателя и ответ шлюза; отказ записывается локально и не означает принятие/завершение вызова для остальных. |
| F06 | Добавлена таблица EmergencyEvents с независимыми состояниями SignalR, внешнего шлюза и Telegram. Внешняя доставка повторяется с постоянным event_id; устаревшие события не запускаются. Шлюз хранит идемпотентные квитанции; создание специалиста и квитанции выполняется одной SQLite-транзакцией. Неподтверждённое сообщение Telegram не дублируется автоматически. |
| F07, F16 | Один управляемый таймер тревоги отменяется при новой тревоге, отбое и закрытии приложения. Отбой сопоставляется с ID события. Очередь речи, текущая SAPI-речь и WAV могут быть остановлены; воспроизведение выполняется на STA. Завершение внешнего события снимает соответствующее окно. |
| F08 | Карта ID отделений сохраняется и применяется в обоих направлениях, включая синтетическое отделение реанимации. |
| F10, F18 | В серверный пакет включена проверенная база знаний. Фильтры роли и филиала применяются к списку, поиску и отдельной статье. Автономные статьи обозначаются явно. Увеличение счётчика просмотров выполняется атомарно. PostgreSQL использует корректное BOOLEAN DEFAULT FALSE. |
| F11 | Записи настроек сериализуются, временные файлы имеют уникальные имена, изменения медицинских статусов переводятся на WPF Dispatcher. |
| F12 | Неизвестный филиал не превращается в AllAgents. Общая рассылка требует явно включённой настройки. |
| F13 | Кабинет ограничен 50 символами, филиал должен быть активным. Переносятся группы соединения, запускается синхронизация справочника. Клиент принимает очистку кабинета. |
| F14 | Тест очистки печати использует имитацию. Очистка диска проверяется на собственном временном каталоге с контрольными файлами. Переходы по reparse points исключены. |
| F15 | GLPI ищет полный логин через anchored contains, проверяет единственный активный результат и точное имя. Создание заявки использует одну сессию, которая закрывается. Mock проверяет реальную семантику запроса. |
| F17 | Службы диагностики хранятся в полях и останавливаются при закрытии. Отложенный запуск отменяется. WMI и очистка очереди выполняются вне UI; запросы и дочерние процессы ограничены по времени. |
| F19 | Пустой межсервисный ключ запрещает уведомления; включение интеграции без ключа отклоняется. Сравнение ключей выполняется за постоянное время, объём запроса и число уведомлений ограничены. |
| F20 | Удалены неиспользуемые HTTP actions/tickets и их кэш. SSE имеет одного асинхронного писателя вместо конкурирующих async void. Общий жизненный цикл тревог вынесен в EmergencyEvents. Удалена неиспользуемая зависимость хаба от TelegramClient. |

Дополнительно исправлена совместимость экрана охраны с действующей Content-Security-Policy: JavaScript, CSS и обработчики событий вынесены из HTML.

## Проверки

- Клиентские тесты: полный набор; конкурентное сохранение 80 раз; отмена отложенного окна после его исходного срока; порядок и отмена языков речи; тесты очистки используют только фикстуры.
- Серверные тесты: ограничения ролей, неизвестный филиал, подмена логина, карта 10 → 3, реальный ID специалиста, отказ без внешнего ack, запрет подтверждения посторонним, HTTP-ошибки и повторы, гонка отмены через второй DbContext, ограничения статей, видимая ошибка Telegram.
- HTTP/SignalR: анонимные white-ack/reset отклоняются, обычный пользователь не имеет права охраны, привязка требует пользовательскую сессию и ключ ПК, агент не может объявить серверный отбой.
- Подготовленный серверный пакет проверяется отдельно от локальных недельных модулей.
- Chromium: настройки и экран охраны под действующей CSP, заголовок авторизации при принятии/сбросе.
- PostgreSQL: аддитивное создание EmergencyEvents и KnowledgeArticles после удаления только новых таблиц в отдельной тестовой БД; рабочая БД не использовалась.
- AudioRONGTA: 9 pytest-проверок с временной SQLite и имитацией диспетчера/SIP, включая отказ от отмены чужого события и отмену во время подготовки настоящего класса диспетчера.
- Подписанный MSI: проверка подписи, подмены манифеста/пакета, загрузки и запрета повторной версии на изолированном сервере.

## Границы и переход

Accepted означает подтверждённый приём внешним шлюзом, а LocalDelivered — завершённую отправку в SignalR. Эти статусы не подтверждают физический звук усилителя или просмотр окна человеком. Реальные медицинские коды и изменения паролей рабочего AD при проверках не запускались.

Серверный пакет собран из свежего снимка действующего сервера с проверенными изменениями и базой знаний. Несвязанные локальные недельные модули, включая ChatPolls, не включены.

Для рабочего перехода требуется согласованное обновление клиента и сервера: старый клиент 1.2.44 не выполняет новую проверенную привязку и не передаёт текущий пароль. Адресная доставка нового сервера требует этой привязки. Перед переключением необходимо выбрать порядок перехода и проверить обновление рабочих ПК; публикация клиентского манифеста должна предшествовать включению строгой привязки в рабочем сервере. Временно возвращать доверие к заявленному логину ради совместимости в подготовленном коде не стали.

Полное косметическое разбиение PetWindow на несколько классов не выполнялось: удалён опасный/неиспользуемый код и выделен жизненный цикл сервера; остальной рефакторинг не требуется для устранения найденных ошибок.
