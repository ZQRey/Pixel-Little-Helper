## 🚀 Текущий спринт: Автоматизация клиента и управление окнами

### 1. [ ] Умный контроль запуска NCALayer (`NcaLayerWatchdog`)
- [ ] **Задержка запуска ~7 минут:** При старте помощника выдерживать задержку ~7 минут, давая операционной системе завершить загрузку автозапуска и фоновых служб.
- [ ] **Проверка активного процесса:** Проверять наличие процесса `ncalayer` в системе (`Process.GetProcessesByName("ncalayer")` / `Get-Process ncalayer`).
- [ ] **Исключение дублирования:** Если процесс уже активен — НЕ запускать повторный экземпляр (предотвращает конфликт и ошибку *«занят порт»*).
- [ ] **Автозапуск при отсутствии:** Если процесса нет — найти исполняемый файл и запустить `ncalayer.exe`.
- [ ] **Оповещение при отсутствии программы:** Если `ncalayer.exe` не найден в стандартных путях системы (`AppData`, `Program Files`, реестр `Run`) — показать пользователю уведомление: *«Приложение NCALayer не найдено в системе»*.

---

### 2. [ ] Проверка пользователей и очистка ресурсов (`SessionWatchdog`)
- [ ] **Таймер проверки (2–3 минуты после старта):** Запускать инспекцию сессий через 2–3 минуты после входа в систему текущего пользователя.
- [ ] **Анализ активных сессий Windows:** Определять количество сессий пользователей в ОС (`WTSEnumerateSessions`, `quser` / `query user`).
- [ ] **Отключение пользователей в «ожидании»:** Если пользователей больше одного:
  - Определить текущего активного пользователя за консолью (например, `hamad`).
  - Найти сессии пользователей в статусе ожидания/блокировки/дисконнекта (например, заблокированная сессия `sadjan`).
  - Корректно завершить/отключить неактивную сессию для освобождения оперативной памяти и ресурсов процессора.
- [ ] **Перезапуск NCALayer после очистки сессий:**
  - Проверить статус процесса `ncalayer`.
  - Если процесс остался от предыдущего пользователя или завис — принудительно завершить его и запустить заново в сессии текущего пользователя.
  - Если процесс не запущен — запустить его.
  - Если NCALayer не найден — уведомить пользователя.

---

### 3. [ ] Режим отображения «Поверх всех окон» (`Topmost`) для окон и диалогов
- [ ] **Окно создания заявки (`TicketWindow`):** Установить `Topmost = true` и привязку `Owner`, чтобы при открытии из режима «Поверх всех окон» форма «Заявка программистам» гарантированно открывалась на переднем плане и не пряталась под другими окнами.
- [ ] **Диалоги и служебные окна помощника:** Гарантировать передний план для `SuperAdminWindow`, всплывающих уведомлений, меню и диалогов подтверждения.
- [ ] **Мессенджер — в обычном режиме:** Окно мессенджера (`MessengerWindow`) должно оставаться в стандартном режиме (`Topmost = false`), чтобы не перекрывать рабочий стол при длительной переписке.
